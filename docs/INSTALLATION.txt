FLASH ONLY ON THE ORIGINAL PIXEL 4 (FLAME) OR PIXEL 4 XL (CORAL)

PREPARE THE PUBLIC TEMPLATE (NO PYTHON NEEDED)

The TEMPLATE.zip contains no EFS backup images. Open it in an archive manager
and place your own raw backups at these exact paths inside the ZIP:

  efs_backup/modemst1  (2097152 bytes)
  efs_backup/modemst2  (2097152 bytes)
  efs_backup/fsg       (2097152 bytes)
  efs_backup/fsc       (131072 bytes)

Use backups from the exact handset being restored, with no filename extensions
or extra subfolder. Save the updated ZIP. META-INF/, install/ and efs_backup/
must remain at its root. See efs_backup/README.txt for repacking instructions.
Do not change installer scripts or SHA256SUMS. Never add dummy/blank substitutes.
The empty template is rejected before restore writes. After adding backups,
keep the personalized ZIP private. A ZIP made with build.py already contains
its backups; skip this preparation and do not replace those embedded images.

FLASH IN ORANGEFOX

1. Complete the ROM installation and all required wipes first.
2. If this package enables DSDS, Android must have initialized Data after
   the last Format Data. Boot Android once if needed, let it finish starting,
   then return to recovery. The installer requires
   Android's existing modem initialization marker. No dialer step is needed.
3. Mount/decrypt Data if this package enables DSDS. An EFS-only package
   does not need Android's settings database and leaves DSDS unchanged.
4. Flash this personal ZIP in OrangeFox/TWRP or use recovery ADB Sideload.
5. Wait for the EFS success message and, for a DSDS package, the DSDS
   success message. Reboot System and check IMEIs and cellular service.

The installer does not reboot automatically. No Magisk/KSU module or
Android boot script is installed. All four supplied backups are copied unchanged.
The public template supports flame and coral. It checks the model, not
ownership of the individual handset. Never share backups between phones.
Locally built personal ZIPs also require their selected model to match.

If the installer reports an error, keep recovery open. Save the printed
log and pre-restore copies before rebooting; recovery RAM is temporary.
EFS writes are not automatically rolled back. A failed DSDS update after
EFS restoration is reported explicitly as failure.

Do not wipe Data after flashing. This is an on-demand restore, not a
permanent provisioning change. It does not enable bootloader relocking.

Never publish this personal ZIP or the raw modem backups it contains.
Source, documentation and updates:
https://github.com/its-hecker/floral-efs-toolkit

If the first Android boot shows 00 but a second restore works, see
DIAGNOSTICS.md and tools/capture_diagnostics.py in this ZIP. Capture the
failed Android boot before returning to recovery, then recovery evidence
before restoring again. The maintainer tested v1.5.2 and confirmed it works
with both DSDS settings saved together. v1.5.4 retains that logic and enables
flame and coral in the shared template and diagnostic collector.
